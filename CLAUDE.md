# CLIP

JUCE 8 clipper plugin (AU, VST3, Standalone). Work is tracked as GitHub issues.

## Layout

- `CMakeLists.txt` at the repo root; JUCE 8.0.15 fetched by CPM into `~/.cache/CPM`
- `Source/Parameters.h` parameter IDs and layout, the only place parameters are defined
- `Source/PluginProcessor.*` owns the APVTS and DSP, routes audio
- `Source/PluginEditor.*` UI
- `Source/dsp/` pure DSP with no GUI deps, so it can be unit tested
- `Tests/` JUCE `UnitTest` console app (`CLIPTests`); add new test files to `CMakeLists.txt`
- `JuceHeader.h` is generated by `juce_generate_juce_header`; don't add a JuceLibraryCode folder

## Build

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build -j
./build/CLIPTests_artefacts/Debug/CLIPTests
```

Verify changes with a real build and the tests, not just a syntax check.

## Notes

- `processBlock` runs on the audio thread: no allocations, locks or logging. Allocate in `prepareToPlay`
- Never rename a parameter ID after release; bump the `ParameterID` version hint for new ones
- Audio to UI data goes through lock free FIFOs or atomics only
- Report any added latency (oversampling) with `setLatencySamples` and keep the dry path aligned
- C++ project, so the global JS/React/Tailwind style rules don't apply; scope, diff, git, and workflow rules do
